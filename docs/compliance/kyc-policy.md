# سياسة اعرف عميلك — KYC

> لا تُجمع بيانات هوية إلا لغرض مشروع ومثبت، وبالحد الأدنى اللازم.

## المراجع

- `REG-002` و`REG-003` في `regulatory-register.md`.
- `SRC-CBOS-AML-ACT-2014` و`SRC-CBOS-AML-2026-08` — الانطباق على دور Ticketty ونموذج الأموال قيد المراجعة القانونية.

## فئات الأطراف

- شركة النقل (Operator) والممثلون والملاك المستفيدون عند وجوب ذلك.
- الوكيل/البائع والمستخدمون ذوو الصلاحيات المالية.
- المسافر/العميل فقط بقدر ما تتطلبه الرحلة أو القانون أو معالجة الدفع.
- مزود الدفع يخضع لعناية Vendor منفصلة، لا يعامل كعميل عادي.

## دورة KYC

1. تحديد الغرض والأساس قبل الجمع.
2. جمع الحد الأدنى مع مصدر كل حقل.
3. التحقق بمصدر معتمد وتسجيل نوعه، لا نسخه بلا ضرورة.
4. حساب فئة المخاطر بواسطة قواعد قابلة للإصدار.
5. اعتماد بشري للحالات المرتفعة.
6. إعادة المراجعة دورياً أو عند Trigger جوهري.
7. انتهاء الغرض → تقييد/حذف وفق سياسة الاحتفاظ.

## ضوابط البيانات

- تشفير الحقول الحساسة، وإخفاؤها في الواجهات والسجلات.
- لا يظهر الرقم القومي كاملاً إلا لصلاحية محددة وسبب مسجل.
- يمنع استخدام بيانات هوية عميل مؤسسة أخرى (tenant isolation).
- لا تُرسل الوثائق لمزود خارجي دون تقييم Vendor وعقد وغرض موثق.

## Evidence

نسخة Consent/Notice عند الحاجة، مصدر التحقق، timestamp، reviewer، نتيجة القرار، policy version، وأي Override مع السبب.
