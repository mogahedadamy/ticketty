# سياسة التحكم في الوصول

## المراجع

- `REG-011` في `regulatory-register.md`.
- القاعدتان 6 و7 في `engineering-principles.md`.

## النموذج

RBAC دقيق مرتبط بالمؤسسة والفرع، مع Context إضافي للحالات المالية والحساسة. الرفض هو الوضع الافتراضي.

## الأدوار الأولية

| Role | النطاق النموذجي |
|---|---|
| OWNER | إدارة المؤسسة دون تجاوز Tenant |
| OPS_MANAGER | المسارات والرحلات والأسطول |
| FINANCE | Ledger والتسوية بتقسيم واجبات |
| STATION_MANAGER | عمليات فرع محدد |
| SELLER / AGENT | بيع/حجز ضمن الفرع والحدود |
| COMPLIANCE | KYC/AML/Policy evidence |
| AUDITOR | قراءة غير قابلة للتعديل وفق تكليف |

## الضوابط

- الصلاحية تفحص Server-side ولا تعتمد على إخفاء زر في React.
- كل Query يتطلب `organizationId` من جلسة موثقة، لا من body العميل.
- العمليات المالية الحساسة تستخدم Maker/Checker عند اعتمادها.
- منح/سحب الصلاحيات يسجل في Audit Log مع السبب والموافق.
- مراجعة ربع سنوية، وفورية عند مغادرة الموظف أو تغير دوره.
- Break-glass محدود المدة، بموافقة وتنبيه ومراجعة لاحقة.
- Service accounts بلا دخول تفاعلي وبأقل Scope وRotation.

## الاختبار

اختبارات سلبية لعبور Tenant، مستخدم معطل، مؤسسة معطلة، صلاحية ناقصة، Branch mismatch، وتغير الصلاحية أثناء جلسة قائمة.
