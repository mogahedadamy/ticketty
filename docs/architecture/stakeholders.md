# أصحاب المصلحة وحدود الثقة

## المستثمر

يحتاج مؤشرات نمو ووحدة اقتصادية ومخاطر واستمرارية. يحصل على تقارير مجمعة ومحدودة؛ لا وصول تلقائي لبيانات هوية الركاب أو التحقيقات.

## الجهة الحكومية / المنظم

تحصل فقط على البيانات والتقارير المخولة قانوناً وبقناة موثقة، مع Source Requirement وApproval وAudit Evidence. لا نبني Backdoor أو وصولاً شاملاً غير منضبط.

## مزود الدفع

طرف خارجي غير موثوق افتراضياً. يتكامل عبر Adapter، برسائل موقعة وIdempotency ومصالحة. لا يقرر Core نجاح الدفع من Redirect العميل ولا يمنحه وصولاً لبيانات خارج الغرض.

## شركة النقل (Operator)

العميل الأساسي وTenant مستقل. بياناته ومستخدموه وفروعه وعملياته معزولة. موظفو Suda-Technologies لا يدخلون بياناته إلا بتفويض دعم محدد المدة ومسجل.

## الوكيل / البائع

صلاحيات محدودة بالمؤسسة والفرع/القناة وحدود التشغيل. لا يصل إلى التقارير المالية أو KYC إلا بمتطلب وصلاحية صريحة.

## المسافر

صاحب بيانات وتذكرة؛ نجمع الحد الأدنى لتقديم الرحلة والمتطلبات المتحققة، ونمنع إعادة الاستخدام غير المتوافق.

## Suda-Technologies

مشغل التقنية وليس مالكاً تلقائياً لكل البيانات أو مؤسسة مالية. مسؤول عن الأمن، الفصل، Evidence، إدارة التغيير، وعدم تقديم ادعاء ترخيص غير مثبت.

## قاعدة التصميم

كل تكامل أو شاشة أو تقرير يحدد: Actor، Tenant، Purpose، Data scope، Permission، Audit event، Retention rule، وRegulatory requirement قبل التنفيذ.
